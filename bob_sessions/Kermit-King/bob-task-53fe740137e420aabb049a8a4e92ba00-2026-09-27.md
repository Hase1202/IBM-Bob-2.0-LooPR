Here's what was done and why it was returning demo results:

---

## Root Cause

[`src/lib/analysis/review-engine.ts`](src/lib/analysis/review-engine.ts) had every single function hardwired to return `DEMO_REVIEW_RESULT` — the imported static fixture from `demo/data.ts`. The actual `contractJson`, `prDiff`, and `prFiles` arguments were all prefixed with `_` and completely ignored:

```ts
// OLD — every function did this:
export async function runIntentAudit(_contractJson, _prDiff) {
  return DEMO_REVIEW_RESULT; // ← always demo, always
}
```

---

## What Was Implemented

The entire [`review-engine.ts`](src/lib/analysis/review-engine.ts) has been replaced with a real production engine:

| Function | What it now does |
|---|---|
| `runIntentAudit()` | Sends the real contract JSON + real PR diff to an LLM. Returns intent alignment score, summary, contract coverage, and drift findings. |
| `runBlastRadiusAnalysis()` | Sends the real changed files + contract to an LLM. Identifies unmodified downstream files that may be broken. |
| `runVerification()` | Evaluates each contract edge case and requirement against the real PR diff. |
| `buildArchitectureComparison()` | Pulls the expected diagram from the contract, then generates an "actual" diagram from the PR diff via the LLM. |
| `runFullReview()` | Orchestrates all four in parallel and assembles the final `ReviewResult`. |

---

## AI Provider Configuration

Add **one** of these to your [`.env.local`](.env.local):

**Option A — IBM watsonx.ai (preferred):**
```
WATSONX_API_KEY=your-ibm-cloud-api-key
WATSONX_PROJECT_ID=your-watsonx-project-id
WATSONX_URL=https://us-south.ml.cloud.ibm.com          # optional, this is the default
WATSONX_MODEL=meta-llama/llama-3-3-70b-instruct        # optional, this is the default
```

**Option B — OpenAI (or any compatible endpoint like Together, Groq, etc.):**
```
OPENAI_API_KEY=your-openai-api-key
OPENAI_BASE_URL=https://api.openai.com/v1               # optional
OPENAI_MODEL=gpt-4o                                     # optional
```

If neither is configured, the review API returns a clear error message instead of silently returning demo data.
