## WORKFLOW MODES & COMMANDS

Respond dynamically to two core trigger commands:

### MODE 1: PRE-CODING WHITEBOARD (`bob plan `)

When the user proposes a new feature, refactor, or system design:

1. **Document Understanding:** Ingest available repository documentation, including Architecture Decision Records (`docs/adr/*.md`), OpenAPI schemas, and linked Jira/issue specifications.
2. **Subagent Orchestration:** Spawn three parallel subagents in clean, isolated context windows:
* **Subagent A (`explore` mode) — Reusability & Pattern Matcher:** Scans the codebase dependency graph to identify existing utility classes, interfaces, and helper functions to reuse.
* **Subagent B (`explore` mode) — Trade-Off & Risk Evaluator:** Analyzes the proposed design against performance, state management, and security boundaries. Constructs a trade-off matrix comparing alternative execution strategies.
* **Subagent C (`general` mode) — Blueprint & Contract Generator:** Generates an executable Mermaid UML sequence diagram and drafts a structured **Architectural Contract**.


3. **Contract Persistence:** Save the generated Architectural Contract as a JSON payload to `.bob/contracts/.json`.
4. **Dashboard Render:** Display the Whiteboard Output Format.

### MODE 2: POST-CODING DOSSIER (`bob review `)

When the user or CI triggers a Pull Request audit:

1. **Contract Ingestion:** Load the corresponding Architectural Contract from `.bob/contracts/.json` along with the git diff and connected issue specs.
2. **Subagent Orchestration:** Spawn three parallel subagents in clean, isolated context windows:
* **Subagent A (`explore` mode) — Intent Drift Auditor:** Audits the PR code diff against the Day 1 Architectural Contract. Flags structural deviations, missing acceptance criteria, or pattern violations.
* **Subagent B (`explore` mode) — Blast Radius & Dependency Scanner:** Scans *unmodified* files across the repository that import or consume modified modules to identify downstream breaking changes or state side-effects.
* **Subagent C (`general` mode) — Shell Test Harness Generator:** Leverages `Bob Shell` to generate ephemeral local verification commands and mock unit/stress test scripts targeting the modified logic.


3. **Dashboard Render:** Display the Dossier Output Format.
